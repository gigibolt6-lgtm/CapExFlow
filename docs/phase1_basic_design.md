# 設備導入稟議作成アプリ Phase 1 基本設計書

## 1. システム構成
本アプリは、ユーザーのローカルPC内で完結するフルスタックWebアプリケーションとして構成する。

- **ブラウザ (Frontend)**: Reactによる直感的な入力インターフェースを提供。
- **サーバー (Backend)**: Python (FastAPI) により、ファイルシステム（JSON）への保存とPDF生成ロジックを担う。

## 2. 技術スタック方針
将来的な実装フェーズでは以下の採用を想定する。

- **Frontend**: React, Vite, TypeScript, Tailwind CSS, Recharts, Framer Motion (UIアニメーション)。
- **Backend**: Python 3.10+, FastAPI, `fpdf2` または `ReportLab` (PDF生成)。
- **Database**: `projects.json` (1ファイルによる簡易DB)。

## 3. データ保存方針 (projects.json)
データベースを使用せず、全ての案件データを単一のJSONファイルで管理する。

### 構成案
```json
{
  "settings": {
     "company_name": "...",
     "standard_discount_rate": 0.05
  },
  "projects": [
    {
      "id": "PRJ-2024-001",
      "title": "第2工場プレス自動化",
      "status": "draft",
      "units": [
        { "id": "U1", "name": "プレス機", "data": { ... } },
        { "id": "U2", "name": "搬送ロボ", "data": { ... } }
      ],
      "overall_summary": { ... }
    }
  ]
}
```

## 4. 計算ユニット方式
案件を複数の「ユニット」に分割することで、複雑な設備構成にも対応可能とする。

- **個別の計算**: 各ユニットで投資額、効果額、BEP等を計算。
- **案件全体の統合**:
  - **合算可能**: 投資額、効果額、固定費、キャッシュフロー。
  - **再計算が必要**: 回収年数、ROI、IRR、BEP稼働率。
    - ※単純平均はせず、合算データから全体指標を導出するロジックを実装する。

## 5. PDF出力方針
「入力は最大、出力は最小」の原則を徹底する。

### 条件付き出力ルール
- **項目単位**: 値が `null`, `undefined`, または空文字（`""`）の場合は行ごと削除。
- **セクション単位**: セクション内の全項目が未入力の場合は、見出しを含めて非表示。
- **表単位**: データがない行は出力せず、表全体がない場合は表を削除。

## 6. MVP (Minimum Viable Product) 範囲
- 案件の基本操作（作成・保存・一覧）。
- 標準的な投資回収指標（回収年数、NPV, IRR）の計算。
- PDF出力機能（現行Excelフォーマット準拠）。

## 7. 将来拡張案
- **画像・レイアウト図添付**: PDFへの自動埋め込み。
- **バックアップ機能**: JSONファイルの自動ローテーション。
- **案件比較機能**: 複数案（案A vs 案B）の対比表生成。
- **計算テンプレート切り替え**: 部門ごとの特有ルールへの対応。
